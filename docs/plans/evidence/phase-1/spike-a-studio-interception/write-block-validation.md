## Findings that shape the real implementation

These corrected wrong assumptions in the original spike brief and are load-bearing for Phase 2/3:

1. **The transaction ID must be Studio's own.** `commitActions` passes `transactionId` generated by Studio's `BufferedDocument`; echoing a different id means `consumeUnresolved` never matches and the pane never settles.
2. **A fabricated base revision cannot work.** `sequentializeListenerEvents` seeds `base.revision` from the pair snapshot and requires an unbroken `previousRev → resultRev` chain; `@sanity/mutator` matches `mut.previousRev === HEAD._rev`. The facade must learn real revisions by tapping `getDocument`/`getDocuments`/`fetch` results.
3. **Draft-not-yet-existing needs a create.** `Document.considerIncoming` only accepts a first entry that is a create — synthesize `createIfNotExists` from the published doc with `transition: 'appear'` and **omit** `previousRev`.
4. **`withConfig`/`clone` must be re-wrapped**, or writes escape: Studio reaches the Actions API via `client.withConfig({apiVersion}).observable.action(...)`.
5. **`type: 'mutation'` is required** on synthetic events (`isMutationEvent` checks it) though it is absent from captured payloads.
6. **Mendoza `effects` are not required for the pair listener** — only the global `*` preview listener consumes them (`applyMutationEventEffects`), which is why non-pair listens must pass through untouched.
7. **Also requires blocking:** `dataRequest('mutate'|'actions')`, raw `request` writes, `mutate`/`create*`/`delete`, and `patch()`/`transaction()` builder `.commit()` (builders bind to the real client and would otherwise bypass the facade entirely).
8. Not covered yet: `client.assets.upload` (asset uploads still reach the network; consistent with D01 default deferring branch assets).
