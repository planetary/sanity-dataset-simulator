| **D13** | Which Studio interception strategy is selected? | TO | **HYBRID — awaiting ratification. Rationale corrected 2026-08-04 (evidence review F2); browser evidence still PARTIAL (F1).** Browser run ([hybrid-validation.md](spike-a-studio-interception/hybrid-validation.md)): Studio boots fully through the proxy, and with the echo facade **disabled** an edit still died at the proxy (`403 blocked:true`) leaving staging byte-identical — a server-side result, and the load-bearing one. The same doc's "0 direct requests to Sanity" is an absence-of-egress claim from a detector known to be blind in that run; it does **not** carry the decision (F1). | **The hybrid is selected because the proxy is the sole security boundary, not because the facade is thin.** Both tracks ran (§0.3 Gate A). **Track A** (`unstable_clientFactory`) is present and functional in 6.8.0, intercepts every client incl. `withConfig` chains, and proved full local editing with 0 network writes — but it is `unstable_`-prefixed beta, and Spike F settled that a client-side facade is not a security boundary and cannot be made into one (bypassable by constructing a fresh client, by raw `fetch`, or by a page-reachable token). **Track B** (HTTP proxy) is a bypass-proof network chokepoint with a default-deny, TDD-pinned write guard, but cannot see intent and cannot use cookie auth over plain-HTTP loopback. **Hybrid** = factory injects `apiHost` so 100% of client-derived traffic (data plane, assets, `/users/me`, and the `<url>/socket/<ds>` WebSocket Studio derives from `config().url`) resolves to the proxy; the proxy enforces. **CORRECTION (F2).** The earlier rationale claimed the differentiator was "injects `apiHost` only (no method wrapping ⇒ no identity hazard)". That was false in the code — `spikeClientFactory` returned `instrument(base, …)` unconditionally, so the validated run had full Track-A wrapping in place and the described topology had never run. Two things changed rather than one sentence: (1) `instrumentedClient.ts` now decides via an exported `shouldInstrument()` truth table, and the pure hybrid (`SPIKE_API_HOST` set, echo off) really does return a bare unwrapped client — asserted with `util.types.isProxy` in [`test/spike-a-client-identity.test.ts`](../../../../packages/sanity-overlay-testkit/test/spike-a-client-identity.test.ts), with the Track-A topology pinned as the opposite case so the probe is non-vacuous. (2) The security argument no longer rests on wrapping at all, so the correction does not move the decision. **Wrapping is not optional in general:** the local-echo facade *is* a method-wrapping Proxy (`localEcho.ts:1035`) — that is how it intercepts and echoes writes — so "no method wrapping" is unobtainable whenever the echo is on. Dropping `instrument` costs only the `__SPIKE_A__` §36.1 call inventory; it does not weaken the write block. **The identity hazard is now a test, not a story.** The ~40k-call resubscribe storm had no artifact (review §3). Its mechanism is `useEffect(…, [client.live])` in `sanity/lib/LiveQueries-rJao7vYj.js:36-45` — an effect whose dependency is read off the client every render. The test simulates 20 000 Studio renders against the real factory and requires **exactly 1 subscribe and 2 client calls**; a deliberately identity-unstable wrapper is kept in the suite as a negative control and produces **20 000 resubscribes / 40 000 calls**, reproducing the historical magnitude. Removing the wrapper memo turns 31 tests red. One residual gap is pinned rather than fixed: real `@sanity/client` method identity is prototype-*global*, and any wrapper narrows it to per-instance. That is safe only because every client Studio puts in a dependency array comes from the memoised `getClient` (`WorkspaceLoader-BRx2afZV.js:8306`), which the test also pins. |
